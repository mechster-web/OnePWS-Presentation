# Scene Design Checklist

Use this before promoting any chapter to `redesignStatus: "redesigned"`.

| Area | Check |
|---|---|
| Scene purpose | Is the chapter context, problem, solution, product, proof, decision or closing? |
| Audience | Is the scene tuned for the intended buyer, operator, architect, consultant or executive? |
| Scene type | Is the archetype selected from the registry rather than invented inline? |
| Primary visual | Does the main image/video clearly show the room, product, operator state or proof? |
| Main message | Is existing content preserved and visually prioritized? |
| Interaction | Is the interaction obvious without a large instruction popup? |
| Narration | Are narration states available, playing, paused, loading and unavailable handled? |
| Motion family | Is the motion family appropriate to the scene purpose? |
| Transition | Does transition metadata avoid over-dramatizing minor scenes? |
| Theme | Is the theme variant selected intentionally? |
| Information density | Is dense content progressively disclosed without deletion? |
| Memory moment | Is this truly a memorable peak, or should it stay restrained? |
| Reduced motion | Does the scene remain clear with minimal motion? |
| Presenter behaviour | Can the presenter move on without waiting for long animation? |
| Autoplay behaviour | Does timing support narration, interaction and scene readiness? |
| Mobile and touch | Are touch targets usable and hover-only interactions avoided? |
| Performance fallback | Does reduced mode remove blur/parallax without breaking layout? |
| Accessibility | Are focus states visible, contrast sufficient and status not colour-only? |
| Media fallback | Is missing media handled cleanly for customers and logged in development? |
| Legacy safety | Are unrelated chapters still using legacy fallback? |
